These are hypothetical compute examples. The equal duration is an arithmetic assumption, not evidence that the cards finish a task in the same time. Separately charged storage, transfer, or services would need to be added under the actual terms.

Per-second billing makes it possible to calculate compute from billable seconds divided by 3,600. Billable preparation, idle periods, and retries still belong in that duration. A finished Python process does not establish that the instance has stopped billing.

## Make two rental quotes comparable

Before picking a rate, align five fields:

- GPU identity: model, variant, and memory specification.

- Rental size: GPU count and whether an entire node is required.

- Purchasing terms: on-demand, interruptible, or committed capacity, with any minimums.

- Included resources: CPU, RAM, storage, and network conditions.

- Lifecycle costs: billable states, retained files, transfer, and separately charged services.

A per-GPU headline can require a multi-GPU booking. Use the actual configuration rented. If an offer is priced per node, use that node price directly instead of multiplying it by GPU count again.

Keep price observations dated. A copied figure from a comparison article may describe an older offer, a different rental tier, or an unavailable configuration.
