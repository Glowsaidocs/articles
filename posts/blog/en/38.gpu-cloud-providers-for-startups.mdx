## 3. Set up a repeatable first experiment

Start with a small, representative job that verifies the complete workflow. Glows.ai lets developers launch NVIDIA GPUs in minutes, but setup time still depends on the selected environment, data, and application.

1. Choose the GPU and environment. Match the model, training method, and memory requirement to the GPU. The Glows.ai image catalog includes PyTorch environments and LLaMA-Factory. Verify the selected image’s Python, CUDA, framework, and library compatibility rather than assuming every recipe runs unchanged.

2. Prepare access and data. Use SSH or JupyterLab to configure the job. Expose only required services and manage access credentials carefully. Confirm dataset permissions and model-license requirements before uploading data or downloading weights. You can upload datasets and model files to Datadrive without starting an instance, so you don't pay for GPU time while files transfer.

3. Run a representative test. Use realistic sequence lengths, batch settings, or request sizes. Record peak GPU memory, throughput, output quality, and billable time. A model fitting into memory for inference does not establish that its training configuration will fit.

4. Test recovery. Save and reload a checkpoint. For training resumption, preserve the required optimizer, scheduler, and other training state as well as weights. Instance disks are cleared on release. Save checkpoints and training data to Datadrive, and use Snapshot to keep your installed environment.

5. Record and release. Version the code, image identifier, dependencies, model, tokenizer, dataset, and settings. Save required artifacts, then stop or release compute according to the provider’s rules. Storage plans and any bound public IPs remain billable until you release them.

An RTX 4090 with 24 GB of VRAM can be a starting point for smaller LoRA or QLoRA experiments. Larger models, longer contexts, or full-parameter training may need more memory or multiple GPUs. Validate the actual configuration before scaling.

## 4. Scale when measurements justify the change

Keep experiments flexible while demand is uncertain. Consider a larger instance or cluster when memory, throughput, or scheduling is limiting progress. Compare the additional capacity against its full cost and the effort needed to operate it.

Glows.ai’s training products include On-Demand Cloud, Bare Metal Clusters, and Virtualized On-Demand Clusters. Confirm available configurations, interconnect, software compatibility, and commercial terms for the workload you plan to run. A long job alone does not prove that dedicated capacity will cost less.

Multiple GPUs do not automatically provide one shared memory pool or a proportional speedup. Distributed training needs an appropriate framework and node topology. Gradient accumulation, mixed precision, and memory-saving techniques also have tradeoffs; measure their effects on runtime and model quality.

### Treat inference as a separate deployment test

Glows.ai offers Inference on Cloud for autoscaling inference and Inference on Dedicated Cloud for isolated inference resources. Check model and adapter compatibility, latency under load, capacity requirements, and recovery behavior before directing customer traffic to a deployment.

With Auto Deploy, Glows.ai creates an instance when a request arrives and releases it after an idle period, which limits charges for idle compute. Expect a cold start on the first request after release. Preserve versioned model artifacts and a tested rollback path rather than assuming training environments transfer unchanged into serving.

### Make collaboration and data handling explicit

Use Glows.ai Team to coordinate shared resources, permissions, and quotas. Assign ownership, document environments, and agree on access and spending policies. Shared workspaces help organize collaboration; reproducibility still depends on the files, versions, and settings your team records.

Before using sensitive data, confirm processing location, access controls, encryption, retention, deletion, and any contractual requirements. Globally distributed infrastructure does not establish a particular residency or compliance guarantee.
