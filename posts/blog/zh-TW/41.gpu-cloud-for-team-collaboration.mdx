# 團隊協作的 GPU 雲端 | Glows.ai Team 指南

最適合團隊協作的 GPU 雲端，應能協助另一位成員接續有價值的實驗：找到合適的資源、存取資料、重建環境，並理解結果與成本。交接順利，共用運算資源才能發揮價值。

Glows.ai Team 將共用 GPU 資源、環境、資料集、權限與配額整合至同一個工作空間。搭配 Glows.ai 的隨需 GPU 選項、目錄中的 AI 環境，以及 SSH/JupyterLab 存取方式，可為 AI 團隊提供實用的協作開發基礎。

本指南說明平台提供的功能，以及如何透過工作方法讓共用資源發揮作用，從小型新創的第一次實驗，一路延伸至可重複執行的訓練或推論流程。

## 比較協作型 GPU 雲端時應看哪些項目

| 需求 | Glows.ai Team 功能 | 團隊應搭配的做法 |
| --- | --- | --- |
| 共用運算 | 共用 GPU 資源 | 指定實驗負責人與預定用途 |
| 一致的起始環境 | 共用環境 | 記錄確切的映像檔與相依套件版本 |
| 共同存取資料 | 共用資料集 | 標明獲授權的版本與資料切分定義 |
| 適當的存取權限 | 權限 | 檢視誰需要存取，以及需要多久 |
| 資源規劃 | 配額 | 約定支出責任、檢查與資源清理方式 |

這項區別很重要。工作空間提供控制功能與共用資源；執行紀錄則說明這些資源如何產生結果。兩者搭配，讓協作更容易重複進行。

## 從另一位隊友能完成的交接開始

選擇一項具代表性的工作：微調試行、模型評估、vLLM API 測試，或 ComfyUI 工作流程。定義可接受的輸出及負責人，再請另一位隊友根據已保存的紀錄重建設定。

對訓練工作，紀錄應包含基礎模型、tokenizer、資料集切分、訓練設定、驗證目標與檢查點位置。對推論測試，應保留模型版本、精度、上下文、請求分布、並行數與啟動設定。對節點圖工作流程，則應保留工作流程、模型檔案、自訂節點與生成參數。

這是對新創有用的採購測試，因為它評估的是下一次迭代，而不只是第一次成功啟動。在小規模試行時發現缺少相依套件，比在下一個交付期限前才發現的成本低。

## 依專案與責任組織資源

在團隊管理的紀錄中使用一致的命名規則。起步時，專案名稱、執行識別碼、負責人與用途就已足夠。明確區分哪些資源用於實驗，哪些支援持續運作的服務。

將這些名稱維護於專案文件或儲存庫，並在人類可讀的標籤旁記錄實際資源識別碼。

Glows.ai Team 的共用 GPU 資源與環境，讓團隊能在工作空間內協調。依實際工作選擇 GPU，確認記憶體、軟體相容性與容量。團隊工作空間不會將分別配置的 GPU 自動組成協同運作的訓練叢集。分散式工作需要適當的拓撲與框架配置。

## 保存精簡的執行清單

在實驗旁保存一份簡潔、易讀的配置紀錄。例如，可使用包含下列欄位的精簡執行紀錄：

```text
project, run_id, owner
code_commit, image_identifier, dependency_versions
model_revision, tokenizer_revision
dataset_version, split_definition, access_requirements
launch_command, settings, seed
validation_target, measured_result, artifact_locations
resource_identifiers, billable_duration, cost_notes
```

憑證應另行儲存。使用環境變數名稱或機密資訊參照，即可描述必要設定，而不暴露密碼或 API 金鑰。

目錄中的 PyTorch、LLaMA-Factory、vLLM 與 ComfyUI 環境，為 Glows.ai 使用者提供不同任務的起始軟體環境。請固定實際選用的環境，並記錄後續新增項目。僅有映像檔名稱，無法涵蓋之後的套件變更、下載的模型或自訂節點。

SSH 與 JupyterLab 提供檢視檔案及日誌的方式，是實用的開發介面；執行清單則保存原本可能只留在某人的 shell 歷史紀錄或 notebook 狀態中的決策。

## 共用資料時，提供版本與存取計畫

能存取資料集，只是可重現實驗的一部分。請標明確切資料集版本、前處理、訓練／驗證切分，以及任何授權限制，並記錄衍生資料與輸出的寫入位置。

避免將一個會不斷變動的資料夾視為完整歷史。隊友應能知道哪一份輸入產生了哪個檢查點或評估結果。將共用輸入資料與單次執行的工作檔案分開，並記錄發布新版資料集的流程。

實例釋放後，實例硬碟上的資料會被清除；共用資料請放在團隊 Datadrive，環境可用 Snapshot 分享給團隊。在投入長時間工作前，先測試能否取回檢查點或輸出。即使工作空間本身仍可使用，也需要完成這些保留與復原檢查。

## 明確界定存取與費用責任

Glows.ai Team 提供權限與配額。利用可用控制功能，讓存取權限與責任相符，並在專案或成員異動時檢視權限。Glows.ai Team 分為 Owner、Admin 與 Member 三種角色，管理員可設定每位成員能使用的資源。

明確指定資源負責人與清理程序。在 Glows.ai Team 中，Owner 可以把 Credit 分配給每位成員，成員只能使用分配到的額度；Admin View 也能查看每位成員的花費。即使團隊尚未採用更自動化的報表流程，專案台帳仍有幫助。

隨需運算可使用以下公式：

運算成本 = GPU 數量 × 每 GPU 小時費率 × 計費時數。

Glows.ai 的運算採按秒計費。紀錄應包含會計費的設定、執行、重試與閒置時間，並一致地納入另行收費的服務。訓練程序結束，不代表實例已停止計費。確認必要輸出已妥善保存後，再檢查資源的實際狀態。

## 測試完整的第二次執行

有效的協作檢查包含四個步驟：

1. 另一位隊友找到獲授權的資料與配置。

2. 根據記錄的設定啟動相容環境。

3. 還原所需產物，並執行相同評估。

4. 能說明結果、資源使用情況與清理狀態。

將缺漏記錄為具體的後續工作，例如缺少相依套件、資料集版本不明、檢查點無法存取，或未記錄啟動參數。數值能否完全重現，可能取決於硬體、運算核心與框架行為；除了隨機種子，也應保留驗收標準。

當共用資源、環境、資料、權限與配額需要整合至同一工作空間時，Glows.ai Team 值得評估。第二次執行可檢驗這些功能如何支援團隊的實際工作流程。

## 常見問題

### Glows.ai Team 提供哪些共用功能？

共用 GPU 資源、環境、資料集、權限與配額。各實驗的專屬設定，請以執行紀錄保存。

### 這對小型新創有幫助嗎？

有，當不只一個人需要檢視、接續或驗證 GPU 工作時就有幫助。先從單一專案與小型交接演練開始，再將流程延伸至更多工作。免費方案最多 3 個席位，小團隊不用付方案費用就能先試用。

### 共用環境會自動保存每一次實驗嗎？

不會。實例釋放後，實例硬碟上的資料會被清除。資料與檢查點請存到 Datadrive，環境用 Snapshot 保存，再把版本與設定記在執行紀錄中。
